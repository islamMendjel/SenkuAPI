     9→## Run 1 — 2026-11-01: Health-aware key dispatch (circuit breaker + in-turn retry)
    10→
    11→**Rung:** 1 (Correctness) + 2 (Usability) + 3 (Performance)
    12→
    13→**Ladder context:** Earlier fixes already shipped: WelcomeScreen
    14→layout rewrite, de-gilded Thinking animation, professional code
    15→blocks (Markdown.tsx), live date/time context in the system prompt
    16→(fixes "June 19, 2023" date hallucination — verified working).
    17→
    18→### Diagnosis
    19→
    20→Live-testing the gateway revealed the round-robin key router had
    21→**zero key-health awareness**. APInex's "Pool key #2" returns
    22→`401 Invalid API key` from the provider, so:
    23→
    24→- Every other request (whenever rotation landed on the dead key)
    25→  silently failed over to the Z.ai cloud runtime — the slow
    26→  fake-streaming path (48-char chunks @ 6ms) instead of the fast
    27→  native provider SSE stream.
    28→- The message metadata row **lied**: it claimed
    29→  "APInex · Pool key #2 · cloud failover" — crediting a provider
    30→  endpoint and a pool key that never served a single token.
    31→- Usage accounting billed the dead key for tokens it never
    32→  generated (usageEvent.keyId + monthly accumulator + lastUsedAt).
    33→
    34→### Change
    35→
    36→New architecture: `pick → try → mark health → retry next key →
    37→cloud failover only when every key failed`.
    38→
    39→- **`src/lib/senku/keyhealth.ts` (new)** — in-memory circuit
    40→  breaker. Auth failure (401/403) = 1 strike → 10-minute quarantine.
    41→  Transient failure (network cut / empty stream) = 2 strikes within
    42→  5 min → 60-second cooldown. Any success clears all strikes.
    43→- **`src/lib/senku/dispatch.ts` (new)** — orchestrator. Round-robins
    44→  pooled keys via the router, retries the *next* key on typed
    45→  failure, never duplicates already-streamed output (retries only
    46→  when zero deltas were emitted), preserves the original coded
    47→  errors for hard pool conditions (no-keys / limiter exhaustion).
    48→- **`src/lib/senku/executor.ts`** — `tryProviderStream` now returns
    49→  a typed `ProviderAttempt` (`auth` | `unreachable` | `empty` +
    50→  `emitted` flag) instead of an opaque `null`. Removed the
    51→  single-key `executeCompletion` (superseded by the dispatcher).
    52→- **`src/lib/senku/router.ts`** — `pickKey(provider, excludeIds?)`:
    53→  skips keys already attempted this turn, deprioritizes quarantined
    54→  keys (probes them as last resort so a recovered key re-enters
    55→  rotation automatically), new `"all-tried"` reason.
    56→- **`src/lib/senku/gateway.ts`** — uses `dispatchCompletion`; bills
    57→  `usageEvent.keyId` / monthly accumulator / `lastUsedAt` only to
    58→  the key that actually served; `keyLabel` is null on cloud
    59→  failover so persisted messages never claim a key they didn't use.
    60→- **`src/app/api/v1/chat/completions/route.ts`** — same dispatch
    61→  resilience; `senku.key` only reported when a pooled key served,
    62→  `senku.failover: true` otherwise.
    63→
    64→### Expected effect
    65→
    66→- A dead key costs at most ONE failed round-trip (~0.5s) per turn,
    67→  then is quarantined for 10 minutes — while healthy keys keep
    68→  serving with native provider streaming (real SSE, lower latency).
    69→- Metadata is honest: "1.8k tokens · APInex · Test key" when the
    70→  pool served; "APInex · cloud failover" (no key claim) only when
    71→  the endpoint is genuinely unreachable.
    72→- Rotated keys self-heal: after the quarantine expires, the key is
    73→  probed once and re-enters rotation if it works again.
    74→
    75→### Verification (all passed)
    76→
    77→- `bun run lint` clean.
    78→- 3/3 unique gateway requests: `servedBy: provider`,
    79→  `keyLabel: Test key` (before: every other request silently
    80→  `zai-cloud` via the dead key).
    81→- `/api/v1/chat/completions`: 200, `senku.key: "Test key"`, correct
    82→  usage, 1.7s including compile.
    83→- Browser golden path: message sent through the UI, reply rendered,
    84→  metadata row reads "1.8k tokens | APInex · Test key", zero console
    85→  or page errors, zero runtime errors in dev.log.
    86→- Test data cleaned (6 test chats + 5 cache rows + 5 orphan usage
    87→  events removed; the 5 seeded demo chats preserved).
    88→
    89→### Known pre-existing flaws (NOT introduced this run, deferred)
    90→
    91→- Mid-stream provider death after partial emission still re-emits
    92→  the full answer from the cloud (client sees partial + full). The
    93→  dispatcher now refuses to *retry keys* in that case (no
    94→  duplication across keys), but a client-side restart marker would
    95→  be needed to fully fix re-emission.
    96→- Breaker state is in-memory: a server restart re-probes dead keys
    97→  once. Acceptable for a single-process personal gateway.

   285→## Run 4 — 2026-11-02: Grounded-answer contract for the search pipeline
   286→
   287→**Rung:** 1 (Correctness) — user-supplied spec: "Retrieved results
   288→are inputs, not truth. The user's question is the contract."
   289→
   290→### Diagnosis
   291→
   292→Run 3 fixed knowledge honesty for NO-search turns. But when search
   293→was ON, the model received three **undated, unranked** snippets and
   294→a one-line directive ("ground your answer, cite domains"). That is
   295→structurally unable to answer time-scoped questions honestly:
   296→
   297→- No dates → the model cannot check whether a source is inside the
   298→  requested scope; it silently converts publication dates into
   299→  release dates (exactly the failure mode the spec forbids).
   300→- No authority signal → a Reddit thread and an official changelog
   301→  arrive with equal weight; forum posts were being cited as
   302→  factual evidence.
   303→- No protocol → nothing told the model to extract the question's
   304→  time scope, classify the retrieval, or admit a PARTIAL/STALE
   305→  result set instead of pad-and-confident.
   306→
   307→Live probe confirmed the raw material was a minefield: for
   308→"latest Gemini model" the engine returned an aggregator claiming
   309→"3.8 Flash since September 2026", another saying "5 days ago",
   310→and a stale Reddit thread about Gemini 2.0 — plus a Reddit post
   311→claiming "on Gemini 5" with no date.
   312→
   313→### Change
   314→
   315→- **`src/lib/senku/grounding.ts` (new)** — the audit primitives:
   316→  `extractDateHint()` (relative "5 days ago" > full date >
   317→  month-year; yearless dates like "March 12" and ambiguous numeric
   318→  dates deliberately return null — an unusable date must not be
   319→  guessed) and `authorityTier()` (official > press/news >
   320→  reference > blog > forum/social, unknown = "web"; ~45 curated
   321→  hosts, deterministic).
   322→- **`search.ts`** — every search path now captures a `dateHint`:
   323→  the Z.ai cloud engine's own `date` field when present, else the

   327→  backward compatible).
   328→- **`constants.ts` — `SEARCH_SYSTEM_DIRECTIVE` rewritten** into the
   329→  full grounded-answer contract: (1) extract the question's
   330→  TIME SCOPE / CLAIM TYPE / PRECISION; (2) audit each result for
   331→  DATE MATCH, AUTHORITY (forum/social can NEVER support a factual
   332→  claim, especially a negative one), RELEVANCE → classify FULL /
   333→  PARTIAL / STALE; (3) answer with a date on every claim, never
   334→  silently broaden or narrow scope, report knowledge boundaries on
   335→  negative claims, and end with exactly one confidence label —

   337→  included verbatim.
   338→- **`searchContextBlock(sources, now)`** — each result line now
   339→  carries `host (tier) · dated: <hint|none stated>`, and the

   342→  "none stated" must stay none — do not guess.
   343→- **`ChatTimeline.tsx`** — the sources card chips now show

   392→## Run 5 — 2026-11-02: Restart marker — no more duplicated answers on mid-stream provider death
   393→
   394→**Rung:** 1 (TRUST) — the flaw logged as deferred in BOTH Run 1
   395→and Run 3, now fixed at the protocol level.
   396→
   397→*Innovation-cadence note: this is run #5 and the mandate asks for
   398→a bold addition by now — but a known, twice-logged data-corruption
   399→bug on the highest rung outranks a feature. Run 6 is committed to
   400→the bold addition.*
   401→
   402→### Diagnosis
   403→
   404→When a pooled provider died MID-STREAM after partial text had
   405→already streamed to the user, the dispatcher correctly refused to
   406→retry other keys (that would duplicate too) but still failed over
   407→to the Z.ai cloud — which re-generates and re-emits the FULL
   408→answer through the same delta channel. The client had already
   409→rendered the partial, so the user saw:
   410→
   411→```
   412→[partial answer from the dead provider][full answer from the cloud]
   413→```
   414→
   415→…a corrupted, duplicated message that also got persisted verbatim.
   416→Rare (needs a mid-stream death) but exactly the kind of thing that
   417→destroys trust in a gateway.
   418→
   419→Live reproduction: a mock OpenAI provider (node:http) that streams
   420→three SSE deltas then `socket.destroy()`s mid-response. Pre-fix
   421→event stream: `delta × 3 → [cloud re-emits everything] → done`
   422→with the client text = partial + full.
   423→
   424→(Simulation subtlety: Bun's `ReadableStream.error()` from a
   425→`Bun.serve` handler closes the connection cleanly from the
   426→client's perspective — the fetch completes "successfully". A real
   427→death needs an actual TCP reset: node:http + `res.socket.destroy()`.
   428→Also learned: the first accidental clean-close run cached a
   429→mock-prefixed answer for 24h — purged.)
   430→
   431→### Change
   432→
   433→New internal SSE event: **`restart`** — fired by the dispatcher at
   434→the exact moment the cloud is about to re-generate AFTER partial
   435→emission. Clients must clear their accumulated text on it.
   436→
   437→- **`dispatch.ts`** — `DispatchParams.onRestart?`; tracks
   438→  `emittedBeforeCloud` (set only on the `attempt.emitted` break —
   439→  the only path where deltas preceded the cloud) and calls
   440→  `onRestart()` before `zaiCloudExec`.
   441→- **`gateway.ts`** — `TurnEvent` union gains `"restart"`;
   442→  `runChatTurn` wires `onRestart → emit({type: "restart"})`.
   443→- **`store.ts`** — `restart` handler: `assistantContent = ""` +
   444→  `phase: "thinking"` so the UI shows the thinking animation
   445→  during the cloud hand-off gap instead of a blank bubble; the
   446→  next delta resets the phase. Final `done.content` (cloud full
   447→  text) then matches the rendered text exactly.
   448→- The v1 OpenAI-compatible route needed NO change: it is
   449→  non-streaming (`onDelta` undefined), so failover there already
   450→  yields one clean JSON — duplication is structurally impossible.
   451→
   452→### Verification (all passed)
   453→
   454→- `bun run lint` clean.
   455→- **Failure E2E** (mock provider streaming 3 deltas then TCP
   456→  reset, via /api/chat/send): `delta × 3 → restart → cloud deltas
   457→  → done servedBy=zai-cloud`; restart-honoring client text =
   458→  cloud answer ONLY; `done.content === client text`; `key: null`
   459→  (no key billed for the cloud's work).
   460→- **Browser golden path** (mock provider active in the UI): sent a
   461→  message, watched partial → thinking → single clean answer;
   462→  rendered text contains ZERO "MOCK-PARTIAL" remnants; provenance
   463→  row honestly reads "… · MockFail · cloud failover · 290 tokens ·
   464→  cache: miss"; 0 console/page errors.
